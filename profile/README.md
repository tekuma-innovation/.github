## Team Onboarding · 团队入门指南

**成员版 · V1.2 · 2026年10月**  
**适用于所有TEKUMA项目｜阅读约5分钟，首次操作约10分钟**

欢迎加入TEKUMA的GitHub协作体系。这是一份面向策划师、城市设计师、建筑师、品牌设计师和项目经理的简明指南。**你不需要会编程，不必安装Git，也不需要改变平时使用的设计软件。**

### 01｜先了解：我们为什么使用GitHub？

**Dropbox存放项目文件，GitHub记录任务、讨论和项目知识。**

| 平台 | 用来做什么 |
| --- | --- |
| **Dropbox** | 继续保存和编辑CAD、Rhino、SketchUp、GIS、PPT、Word、PDF、图片、视频等设计成果。 |
| **GitHub** | 查看工作任务、讨论与确认修改、记录进度、链接Dropbox成果，以及积累项目研究和策划文本。 |

每个项目拥有自己的GitHub仓库（Repository）；加入公司组织后，你会根据参与的项目获得相应仓库的访问权限。**不需要把Dropbox的文件整体搬到GitHub。**

### 02｜第一次加入：按顺序完成四步

1. **注册/登录个人GitHub账号。** 打开 [github.com](https://github.com)，用自己的账号登录，并开启双因素认证（2FA）。不要注册共用账号。
2. **接受TEKUMA邀请。** 查收邮件或GitHub通知，接受 `tekuma-innovation` 发出的组织邀请。公司主页：[github.com/tekuma-innovation](https://github.com/tekuma-innovation)。
3. **进入你参与的项目。** 项目负责人会发送仓库链接，并为你开通权限。打开链接后，先看 `README`（项目首页），了解项目概况、当前工作和Dropbox入口。
4. **找到任务列表并试着评论。** 在项目仓库点击 `Issues`，打开负责人指定的入门任务或适合讨论的任务，留言确认自己已能正常进入。

> **看不到项目、出现404？** 请先确认已经接受组织邀请，再让项目负责人检查仓库授权。加入TEKUMA组织并不代表自动拥有所有私有项目的访问权限。

### 03｜每天怎么用？

**看GitHub任务 → 在Dropbox完成工作 → 回GitHub更新进度 → 负责人确认。**

| 日常动作 | 操作方式 |
| --- | --- |
| **接任务** | 打开对应 `Issue`，看清目标、负责人、截止日期和交付要求。 |
| **做工作** | 使用熟悉的软件工作，成果按原有规则保存到Dropbox。 |
| **汇报进展** | 在Issue评论进展、提出问题、@相关同事，并附上Dropbox成果链接。 |
| **反馈与验收** | 负责人在Issue中确认、提出修改意见，完成后关闭任务。 |

微信和会议仍然可以讨论。**不需要把每条聊天复制到GitHub**；只要把关键任务、重要修改意见与已经确认的决策记录下来。

### 04｜一张合格的任务卡长什么样？

在项目仓库点击 `Issues → New issue`，写清四件事即可：**做什么、谁负责、什么时候完成、成果在哪里。**

> **标题：**【调研】整理公共空间更新案例  
> **任务：** 选择5个参考案例，每个提供图片、基本资料和一句值得借鉴的经验。  
> **负责人 / 截止时间：** @相关同事 / 按项目计划确定  
> **成果：** 完成后附Dropbox文件链接，由项目负责人确认。

任务卡不必写得很长，但应让其他同事快速理解工作要求。

### 05｜首次使用检查清单

- [ ] 已登录个人GitHub账号，并接受TEKUMA组织邀请。
- [ ] 已收到自己参与项目的仓库链接，能够正常打开。
- [ ] 已看过项目README，知道从哪里进入Dropbox项目文件夹。
- [ ] 已打开Issues，并完成一次试用评论。
- [ ] 知道以后在哪里看任务、在哪里汇报进度及贴成果链接。

### 06｜常见问题

**需要先学Git、Commit、Branch或Pull Request吗？**  
不需要。第一阶段只使用GitHub网页、README和Issues；编辑Markdown等内容由需要的成员另行培训。

**为什么GitHub上看不到全部项目？**  
许多客户项目是私有仓库，成员只会被授权访问所参与的项目。

**Dropbox链接打不开，或担心客户资料泄露？**  
联系项目负责人核实共享权限。不要自行把客户文件改成“所有持链接者可访问”，也不要向公开仓库上传客户资料。
